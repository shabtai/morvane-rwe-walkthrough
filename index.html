Introduction

Real-world data is messy. Claims, pharmacy fills, lab results and doctors' notes each have their own codes, habits and hidden errors. In a normal study, most of the time goes into learning these by hand. Most wrong answers come from missing one of them.

Our system does this learning first, on its own, and writes down everything it finds. We call this step enrich, and its output the board. Every later step — matching patients, running the answer steps — reads the board. Enrich is the heart of the system: if the board is right, the rest follows.

Learn the data first

Enrich reads every table, column and note before any question is asked. It needs no data dictionary, no setup and no fixed word lists, so it works on data it has never seen.

Prove, don't guess

Each meaning on the board is backed by counts from the data. Risky decisions, like joining two member IDs into one person, need two separate readers to agree.

Trace every number

Answers come from settings files and fixed code. Every figure points to its rule and its query, and a rerun gives the same numbers.

Each step is saved as a layer. Any new step, analysis or query runs on top of the layers already built. It does not start from zero: it reuses the board's meanings, the matched people, the cohort and the rules.

  • A new question on the same cohort, such as a lab trend or a subgroup, uses the confirmed 28 patients and their joined histories.
  • A new study on the same data uses the board as it is. Only the new rules are written.
  • A direct query on the cleaned tables already knows which rows are voided, reversed or carry a fake value.
  • A report, such as a payer dossier, uses the traced figures, so each number keeps its link to its rule and query.

Enrich: the heart of the system

Before any study, an AI layer reads every table, column and note and writes down what each one means. It proves each meaning against the data itself. The output is a board: a shared map of meanings, links between tables, and data problems. Every later step reads this board instead of guessing.

OutcomeA board with a proven meaning for all 39 columns, 4 tested links between tables, 13 data problems and 118 notes turned into fixed fields. Time: 91 minutes.

Reading the 118 clinical notes

Notes are free text. A note that says "Morvane" may mean the patient has it, may not have it, or has a relative with it. The note reader puts each note in a category and pulls out the gene result, the test source, the sample date and any old patient ID. A second reader checks each field. Every value must be a quote from the note.

Who is who

Some patients got a new member ID when their insurance card changed. If we count IDs, we count them twice and split their history. But some pairs of IDs look alike and are in fact two different people. This step decides, pair by pair, which IDs belong to one person.

Outcome1,231 member IDs became 1,226 people. All 5 true pairs were joined, and no wrong pairs.

How two IDs become one person

Code finds IDs that look like the same person: one ID ends and a new one starts soon after. Two separate AI readers then check each pair. A pair is joined only when both agree. If not, the IDs stay apart, because a wrong join mixes two patients.

Q1 and Q2 are configurable steps

Each answer step is fixed code driven by a short settings file. The settings hold the study choices: what counts as a case, which test confirms it, what the diagnosis date is, where the journey ends. To change a definition, or run the same study on another rare disease, you change the settings, not the code.

An AI checks the settings against the board and changes one only when the data proves it wrong. A person can read and approve every change. Each number keeps a link to the setting and query behind it, and a rerun gives the same numbers.

StepWhat you can set
Q1 CohortCase definition · confirming tests · how gene results are read · billing codes to compare against
Q2 JourneyDiagnosis date · related conditions · specialties · end specialty · minimum enrollment before the first sign

Example from this run: the AI found 5 confirmed patients held back by a setting that did not know some gene result labels. It fixed the setting, and the cohort went from 23 to 28. What triggered the change: six lab rows named two NRB3 variants but no class label. Other lab rows in the same file label each of those four variants PATHOGENIC or Class 5, and four of the six results are also confirmed by a lab addendum note. The AI cited these rows in the setting's reason. It had no access to the answer key: its only tools read the settings, the figures and the study tables.

The answer key says 1,222 days. Our 1,232 is inside the ±15 day tolerance. The gap comes from 6 patients whose diagnosis date was taken from the note date, which is a few days after the sample date. We kept this number as the run produced it, on purpose: it is within tolerance, and we show the run as it ran.
